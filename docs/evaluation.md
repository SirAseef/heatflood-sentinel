# Evaluation protocol

All reported numbers are generated by `make benchmark` / `make report` from run artefacts and collected in
[`results/RESULTS.md`](../results/RESULTS.md). The test set is calendar year **2022** and is never used for model
selection, calibration or thresholds.

## Continuous forecasts (RQ2)

* RMSE, MAE, Nash–Sutcliffe efficiency (NSE), and skill scores `1 − RMSE_model / RMSE_ref` against persistence and
  climatology.
* **Significance:** Diebold–Mariano test on squared-error loss differentials with a moving-block bootstrap 95 % CI of
  the RMSE difference; Holm correction across the family of comparisons. A "winner" is declared only if the Holm
  p < 0.05 and the CI excludes zero (`results/tables/significance_*.csv`).
* LSTM daily results are reported across 3 seeds (`results/tables/lstm_daily_seeds.csv`).

## Detection

* Contingency metrics: POD, FAR, CSI, F1 at the calibrated threshold; threshold-free PR-AUC, ROC-AUC; Brier score
  and reliability diagram (`results/figures/reliability_heatwave.png`).
* Baseline: **rule persistence** (today's label is tomorrow's forecast). Because hazards are persistent, this baseline
  is strong and often wins on CSI; we report it rather than hide it.

## Streaming (RQ3)

* Throughput (messages/s, GB/h), micro-batch latency p50/p95/p99, and **event-time → alert end-to-end latency**
  (replay-emission time to alert emission, so it includes queueing in the micro-batch).
* Chaos scenarios over the first 31 daily batches: duplicates, corrupt payloads, out-of-order, delayed beyond the
  watermark, missing hours, a 3-day source outage, and kill/restart from checkpoint. Reported: DLQ size, alert count,
  duplicate alert events, and whether the alert stream is identical to the clean baseline.

## Scalability (RQ4)

* E1 data volume ×1/×2/×4 (rows/s, GB/h), E2 worker processes 1/2 (speed-up, efficiency), E3 trigger interval
  (6/24/72-h micro-batches). Executed on a 2-vCPU node with the local runtime; cluster-level Spark scaling is not
  claimed (DEVIATIONS.md D6).

## Honesty rules used in this repository

1. Baselines are always shown next to models, including where they win.
2. Proxy labels are named as proxies; leakage-prone setups are flagged (DEVIATIONS.md D1).
3. Nothing in `results/` is hand-edited; `make report` regenerates `RESULTS.md`, LaTeX tables and figures.
